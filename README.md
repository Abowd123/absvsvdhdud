# GitHub ZIP Uploader (APK) - المرحلة 1: التجهيز

## اللي انعمل
- مشروع Capacitor 6 جاهز (`capacitor.config.json`) باسم الحزمة `com.akllk.ghzipuploader`.
- واجهة v1.0 (xt.html) منسوخة إلى `www/index.html`.
- كل المكتبات الخارجية (JSZip 3.10.1، CryptoJS 4.2.0، Font Awesome 6.5.1) صارت محلية في `www/vendor` بدل CDN، عشان التطبيق يشتغل حتى لو النت ضعيف.
- أيقونة + شاشة بداية في `resources/` (تتولد تلقائياً لكل المقاسات).
- GitHub Actions يبني APK تلقائياً مع كل push على main.

## المتطلبات (لو بتبني على جهازك)
Node 20، JDK 17، Android Studio (Android SDK).

## البناء محلياً
```bash
npm install
npm run setup:android   # أول مرة فقط: ينشئ مجلد android + الأيقونات
npm run apk:debug       # الناتج: android/app/build/outputs/apk/debug/app-debug.apk
```

## البناء بدون جهاز (الأسهل)
1. ارفع هذا المجلد لمستودع على GitHub.
2. تبويب **Actions** ← **Build APK** ← Run workflow.
3. نزّل الـ APK من Artifacts.

## الخطوة الجاية (المرحلة 2)
نقل تخزين التوكن من localStorage المشفر إلى Android Keystore.

# المرحلة 2: المصادقة والتخزين الآمن ✅
- التوكن صار يتحفظ في **Android Keystore** عبر `capacitor-secure-storage-plugin` (مشفّر بالعتاد)، وما يتحفظ أبداً في localStorage على الجهاز.
- ترحيل تلقائي: لو فيه توكن قديم محفوظ من نسخة الويب، ينتقل للـ Keystore ويُحذف من localStorage.
- إلغاء "Remember this device" يمسح التوكن المحفوظ.
- "قطع الاتصال" يمسح التوكن من Keystore.
- "مسح الكاش" ما يلمس التوكن.
- في المتصفح العادي (للتجربة) يرجع تلقائياً للتخزين المشفر القديم.

بعد السحب: `npm install && npx cap sync android` عشان ينضاف الـ plugin.

# المرحلة 4: مدير ZIP ✅
- **فك ضغط عند الطلب**: الملفات ما تنفك كلها في الذاكرة وقت الفتح، كل ملف ينفك لما نحتاجه (معاينة / هاش / رفع) وما يُحفظ بعدها. مهم للجوالات.
- **تجاهل ملفات النظام**: `__MACOSX/`، `._*`، `.DS_Store`، `Thumbs.db`، `desktop.ini`.
- **إصلاح**: النسخة القديمة كانت تحذف أي ملف مخفي داخل مجلد (مثل `src/.env` أو `.github/workflows`)، الحين فيه خيار "Include hidden files" مفعّل افتراضياً.
- **إزالة المجلد الجذر**: لو كل الـ ZIP داخل مجلد واحد (مثل `project-main/`) يتشال تلقائياً، مع خيار لإيقافه.
- **حماية المسارات**: منع `..` والمسارات الفاضية ومجلد `.git`، وتحويل `\` إلى `/` (ملفات ZIP من ويندوز).
- **حدود GitHub**: الملفات فوق 100MB تتعلّم بالأحمر وما تنحدد، وفوق 50MB تحذير.
- ملخص بعدد الملفات المتجاهلة/المحجوبة تحت الخيارات.

مؤجل: استقبال ZIP من "مشاركة" في أندرويد، يحتاج تعديل native ونسويه بعد أول بناء ناجح.

# المرحلة 5: محرك الرفع (Git Data API) ✅
**commit واحد لكل عملية رفع** بدل commit لكل ملف:
1. قراءة رأس الفرع وشجرة المستودع.
2. الملفات النصية الصغيرة (≤512KB) تنرسل داخل طلب الشجرة مباشرة (بدون طلب لكل ملف)، والملفات الثنائية تنرفع كـ blobs بالتوازي.
3. بناء الشجرة على دفعات (≤300 ملف / 6MB لكل طلب) ← commit ← تحديث الفرع.

**إصلاحات لأخطاء في v1.0:**
- مقارنة "مطابق" كانت تقارن SHA-256 المحلي بـ SHA-1 حق GitHub، يعني ما تتطابق أبداً وكل ملف يعاد رفعه. الحين نحسب git blob SHA-1 نفس GitHub.
- الرفع المتوازي بـ Contents API على نفس الفرع كان يسبب تعارضات 409.
- إعادة المحاولة كانت تشتغل على أي خطأ رسالته فيها رقم 5.
- الـ Dry Run كان يفشل على المستودعات الفاضية.

**مميزات:**
- **ذري**: الإلغاء أو الفشل قبل الـ commit = المستودع ما يتغير أبداً.
- مستودع فاضي: أول ملف ينرفع بـ Contents API لإنشاء أول commit، والباقي بالطريقة الجديدة.
- لو أحد دفع على الفرع أثناء الرفع: يعيد البناء على الرأس الجديد (بدون force push، وما يمسح شغل أحد).
- انتظار تلقائي عند حدود GitHub (rate limit / secondary rate limit) بدون ما يحسبها محاولة فاشلة.
- يحافظ على صلاحية التنفيذ (مثل `gradlew`) من الـ ZIP، ويحدّثها لو تغيرت.
- رابط مباشر للـ commit بعد الانتهاء.

**الاختبار:** `node tests/upload-engine.mock.mjs` يشغّل المحرك على GitHub وهمي (مستودع فاضي، إعادة رفع مطابق، وضع "جديد فقط"، فرع تحرك أثناء الرفع، إلغاء).

# المرحلة 6: التقارير والإعدادات ✅
**التقارير**
- **سجل عمليات الرفع** في صفحة History: التاريخ، المستودع والفرع، رابط الـ commit، النتيجة، عدد الملفات (+جديد ~محدّث =مطابق/متخطى ✗فاشل)، المدة. آخر 50 عملية.
- زر **Export Report** بعد كل رفع: تقرير CSV لكل ملف في العملية.
- **التصدير على أندرويد**: في v1.0 كان التصدير ينزّل ملف عن طريق رابط في المتصفح، وهذا ما يشتغل داخل WebView حق أندرويد. الحين الملف ينحفظ ويفتح قائمة المشاركة (Drive، الملفات، واتساب...) عبر `@capacitor/filesystem` + `@capacitor/share`. في المتصفح العادي يرجع للتنزيل العادي.
- CSV فيه BOM عشان العربي يطلع صح في Excel، وحماية من حقن المعادلات (`=`, `+`, `-`, `@`).
- أداء: السجل كان يعيد تشفير التخزين كامل مع كل ملف، يعني آلاف عمليات التشفير لـ ZIP كبير. الحين الحفظ مجمّع كل 800ms.

**الإعدادات**
- الثيمات (Midnight / Dim) كانت موجودة في القائمة بدون أي تنسيق، يعني ما تغير شي. الحين تشتغل.
- "Chunk Size" ما كان مستخدم أصلاً، استبدلته بـ **Inline text files up to (KB)** (افتراضي 512): الملفات النصية الأصغر منه تنرسل داخل طلب الشجرة.
- أقصى رفع متوازي صار 6 (أكثر من كذا يجيب حدود GitHub الثانوية).
- **Auto-save** صار فعلاً يحفظ مع كل تغيير (كان مجرد checkbox بدون أثر).

بعد السحب: `npm install && npx cap sync android`.
